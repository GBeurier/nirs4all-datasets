# Review of dataset curation integration

This review covers Denis Cornet's [PR #25](https://github.com/GBeurier/nirs4all-datasets/pull/25), headed by [0d8fbed2](https://github.com/GBeurier/nirs4all-datasets/commit/0d8fbed2e7c1a74451d4132e37d9737cb896155e), and the subsequent integration and corrections in [#26](https://github.com/GBeurier/nirs4all-datasets/pull/26), [#27](https://github.com/GBeurier/nirs4all-datasets/pull/27), and [#30](https://github.com/GBeurier/nirs4all-datasets/pull/30). Attribution below follows the implementation history, not the PR in which a problem was discovered.

## Useful contributions

PR #25 introduced versioned source-specific curation contracts, traceable M/Y and identity views, observation-grain joins, explicit missing-value rules, and OSSL soilsite enrichment. These are useful catalog responsibilities: they preserve provenance and make scientific assumptions reviewable. Its UCPH response and OSSL identity work also provides concrete source-specific evidence. Later work qualified source semantics and made descriptor types override source storage types; see [d80b98e8](https://github.com/GBeurier/nirs4all-datasets/commit/d80b98e8) and [f51853d4](https://github.com/GBeurier/nirs4all-datasets/commit/f51853d4).

## Findings and corrections

The current working-tree corrections address three consistency defects:

1. **Declared normalization and renames.** The descriptor-to-curation wrapper added in [d80b98e8](https://github.com/GBeurier/nirs4all-datasets/commit/d80b98e8) did not carry all declared missing tokens, numeric sentinels and renamed column identities into curated views. As a result, those views could disagree with canonical variables. `src/nirs4all_datasets/curation.py` now propagates the directives and preserves explicit source overrides through `schema.py` serialization. This wrapper was follow-up work, not an original PR #25 implementation.
2. **Transitive target dependencies.** The direct declared-dependency exclusion was added in [d80b98e8](https://github.com/GBeurier/nirs4all-datasets/commit/d80b98e8), with alias handling improved in [21db1183](https://github.com/GBeurier/nirs4all-datasets/commit/21db1183). A predictor derived through another declared variable could still expose target information. `curation.py` now follows the declared dependency closure in curated and consumer views. This is a local guard, not a claim of complete split or fit leakage enforcement.
3. **Processing identity.** [abccf0b8](https://github.com/GBeurier/nirs4all-datasets/commit/abccf0b8) added normalization directives to `src/nirs4all_datasets/manifest.py`'s processing hash, but type, role, unit and dependency changes also affect curated outputs. The current hash includes the variable curation directives, including explicit overrides, so those changes invalidate affected caches. Historical manifests and outputs must not be edited to simulate a rebuild.

Existing private and anonymized tiers govern redistribution, not necessarily whether an upstream source is accessible. Those tiers and pre-existing French project material should not be attributed wholesale to PR #25. Review individual provenance and rights before changing a tier; new project content follows the English language policy.

## Ownership and validation

Datasets owns source declarations, evidence, access and redistribution rights, curation policy, cache identity, manifests and cards. Formats owns vendor parsers; IO owns loading and assembly. Methods owns reusable numerical kernels and their native ABI, with thin language facades. A neutral IO normalization contract and DAG identity/split enforcement are future work, not changes authorized by this review. See the [curation ownership roadmap](curation_ownership_roadmap.md).

Focused regression coverage should exercise declared renames, missing tokens and sentinels, explicit dialect/type overrides, transitive target dependencies, and cache invalidation, including descriptor serialization. `tests/test_curation.py` and `tests/test_curation_cache_identity.py` are the relevant suites. A read-only audit on 2026-10-30 called `curate_bundle` successfully for all 297 local source bundles, including 16 OSSL bundles using the original soilsite input with SHA-256 `7dffacfbbce8f1d77b5f76f33b2182e963bb846bcd8e56a0df1fa0dc6974b6b2`. This establishes that the calls completed, not that existing canonical bytes match new outputs: no old canonical curation directories were available for comparison.

The native second-difference MAD integration reuses the global `diagnostics.spectral_noise_proxy` procedure already in Methods 1.3.10 and ABI 2.20. Its bandwise output extension is under development through the existing generic C ABI; it adds no duplicate function or ABI bump. Before a package rollout of bandwise results, release the extension and verify a clean installation. The Datasets `methods` extra requires Methods 1.3.10 or newer and scikit-learn. Rebuild and requalify affected artifacts from verified inputs after the processing hash change. Existing PCA qualification remains until the native method matches its complete protocol; the presence of a related kernel alone does not establish parity. Record final repository and extension gate results separately.
